# Security Notes & Cryptographic Audit Findings

## 1. Upstream Vulnerability in `@privacyresearch/libsignal-protocol-typescript` (Inbound PreKey TOFU Bypass)

### Description
In `@privacyresearch/libsignal-protocol-typescript` (specifically `SessionBuilder.processV3` in `lib/session-builder.js:L230`), the library calls `isTrustedIdentity` without awaiting the returned promise:
```javascript
// Upstream line 230 in lib/session-builder.js:
const trusted = this.storage.isTrustedIdentity(this.remoteAddress.name, uint8ArrayToArrayBuffer(message.identityKey), Direction.RECEIVING);
if (!trusted) {
    throw new Error(`Unknown identity key: ...`);
}
```
Because `SignalProtocolStore.isTrustedIdentity` is an `async` function returning `Promise<boolean>`, the un-awaited `Promise` object evaluates as truthy in JavaScript (`Boolean(Promise) === true`). Consequently, `if (!trusted)` never evaluates to `true`, and the library's internal check is silently bypassed during inbound initial `PreKeyWhisperMessage` (type 3) handshakes.

### Implemented Patch
In `hichat/src/cryptoUtils.js` (`decryptMessage`), before invoking `cipher.decryptPreKeyWhisperMessage()`, we parse the sender's `identityKey` directly from the `PreKeyWhisperMessage` protobuf header using `@privacyresearch/libsignal-protocol-protobuf-ts` and execute:
```javascript
const isTrusted = await store.isTrustedIdentity(remoteUsername, senderIdKey, Direction.RECEIVING);
if (!isTrusted) {
  throw new IdentityKeyChangedError(`Identity key changed for sender ${remoteUsername}. Inbound message decryption aborted.`);
}
```
This guarantees:
1. The trust check runs strictly **before** `decryptPreKeyWhisperMessage()` is called.
2. If the check returns `false`, execution immediately aborts with `IdentityKeyChangedError`.
3. `saveIdentity()` and `storeSession()` are **never invoked** for the untrusted key, preventing stealth re-keys or malicious identity overwrites.

## 2. Shared Symmetric Safety Numbers

* **Ordering:** Safety numbers are generated by sorting both parties' raw public identity keys lexicographically by byte values (`compareByteArrays`), guaranteeing strict symmetry: `computeSafetyNumber(A, B) === computeSafetyNumber(B, A)` regardless of argument order or usernames.
* **Format:** SHA-256 digest formatted into 8 space-separated 5-digit numeric blocks (Signal standard format).
